# Mandate and Ministry: instructions for future agents

Read [docs/MOD-CURRENT-STATE.md](docs/MOD-CURRENT-STATE.md) before planning or editing gameplay. It is the maintained entry point for implemented behavior, module contracts, save compatibility, generation and verification. Read the linked subsystem document for the feature being changed. Historical proposals are not proof that a feature exists.

## Required boundaries

- Work only in this mod. Installed vanilla and Workshop files are reference inputs; never edit them.
- Personnel is accepted gameplay. Preserve appointments, custody/jurisdictions, candidate scoring, marks, tasks, patronage, examination honors and central ministerial succession unless the user explicitly requests a change to them. Revenue work must not rewrite these modules to obtain convenient fiscal hooks.
- The custom Censor–Justice investigation/trial/register system was removed at the user's request. Do not resurrect it. Its small shared/inert compatibility APIs support Personnel and old saves. Passive financial receipts are not a new prosecution system.
- Public Treasury, personal Gold, provincial accounts and the imperial treasury are distinct. Never substitute Gold or create matching income to conceal a failed Treasury payment.
- Institutional state belongs to its office/project/realm. A character event is a temporary reviewer, not the owner of that state. Recheck office identity, current law, eligibility, cash and duplicate-execution guards at commitment.
- Keep decisions role-owned, names consistent and interactions in the shared Ministry category. Follow [docs/EVENT-DESIGN.md](docs/EVENT-DESIGN.md). Describe the actual payer, recipient, amount and authorization; show relevant consequences only.

## Editing and verification

- `tools/build_common_fund.py` regenerates common-fund runtime files and applies upgrades through dev.61. Edit the generator/templates as well as any authored inputs, then run the full builder. Do not run an upgrade script alone on an already upgraded tree. Do not hand-edit generated output and leave it inconsistent with its source.
- Dev.62 adds the separately authorized Censorate. `tools/build_censor.py` and `tools/templates/censor/` are its sources; the full staged common-fund builder generates it after the unchanged dev.61 fiscal upgrades and runs `tools/verify_censor.py`. Read `docs/CENSOR-IMPLEMENTATION.md` and `docs/CENSOR-TESTING.md`. Do not restore the removed case/trial/register, edit generated Censor files alone, turn its read-only receipts into automatic crimes, or bypass accepted Personnel custody during imperial removal.
- Dev.66 adds the separately authorized Justice module. Read `docs/JUSTICE-IMPLEMENTATION.md` and `docs/JUSTICE-TESTING.md`. Sources are `tools/build_justice.py`, `tools/build_justice_events.py` and `tools/templates/justice/`; the full staged builder generates it after Censor and runs `tools/verify_justice.py`. The old `mam_cj_*` register/trial remains removed. New institutional proceedings use `mam_justice.*`/`mam_jus_*`, current native authority/costs, actual custodian/recipient consent and an explicit prospective imperial-warrant bridge. Never make a passive receipt/accusation an automatic crime, confuse a broad native pardon with selective withdrawal of this module's warrant, replay consumed rights/actions, or transfer personal misconduct to an office successor. `docs/JUSTICE-NATIVE-BOUNDARIES.json` is an audited native pin registry; compare source drift deliberately, never refresh pins just to pass. Preserve the native transaction lease and exact-cost/native-acceptance compiler. No Gold or matching-income substitute for a failed Treasury charge.
- Preserve the user's developer hot reload. The builder now generates and runs checks in an isolated temporary copy, then atomically replaces only final changed files in the live mod. Do not bypass staging or rewrite intermediate upgrade versions into watched folders. The internal staging environment flag is restricted to its temporary tree. Unchanged files must not be rewritten merely to force a reload. This is per-file publication, not a guarantee that CK3 hot-reloads every data category safely.
- If the desktop sandbox's default temporary directory is not writable, set `MAM_BUILD_STAGING_DIR` to an authorized writable location outside this mod (for example, the task's separate writable scratch root). Do not fall back to generating inside watched `common`, `events` or `localization` folders. The staging parent is configurable; no game process or launch setting is disabled.
- `docs/COMMON-FUND-CONTRIBUTION-KEYS.json` is an append-only saved identity registry. Never renumber or reuse a project/contribution key. Retain old event IDs, case kinds and paid-grant compatibility unless a migration is explicitly designed.
- Native override manifests and protected hashes are evidence, not test fixtures to update until a failing check goes away. A game update requires a deliberate native-source comparison before rebuilding; do not bypass the generator's source-drift refusal.
- Run `tools/verify_revenue_source.py`, `tools/verify_common_fund.py`, `tools/verify_project_contributions.py` and `tools/verify_auto_projects.py` for fiscal/project changes. The last two cover native callback structure and temporary/permanent target collisions found in engine logs. Run `tools/verify_senior_jurisdiction.py` for title/custody work. Source/model checks are not CK3 execution or visual/AI testing.
- Run `tools/verify_common_fund_scheduler.py` for scheduling, adoption, succession or fiscal-priority changes. Due reconciliation is driven by the weekly sovereign lease, with a native quarterly recovery hook; do not reintroduce the undocumented `monthly_playable_pulse`. The 25-day due gate normally settles every 28 days under weekly polling. Existing overdue saves settle once, without historical catch-up transfers.
- Run `tools/verify_project_edge_cases.py` and `tools/verify_completion_safety.py` for starting grants or native campaign/completion callbacks. Wall types 10–12 are imperial work; types 1 and 17 retain their approved foreign-border exception and native site rules. Provincial types keep their exact jurisdiction. Starting requests recheck native eligibility and price before payment. Native campaign callbacks bind the saved live war; native campaigns can span multiple wars. Never replay a funded pledge or recreate a war because its old link ended. Native project replacements are explicit in `post_replacements`; event/CB safety overrides are pinned in `tools/templates/revenue_native_campaign_safety.json`. Do not broaden these narrow guards, refresh native hashes to excuse drift, or award a successor a dead contributor's personal rewards.
- Keep `.txt`/`.yml` game files UTF-8 with BOM; Markdown/JSON/Python use UTF-8. Preserve installed-game syntax rather than inventing API names.
- Background invoice retries must stay nonmodal while approval is pending. The explicit/manual UI marker is reset by every scheduled worker. A campaign war is led by the Marshal; inspect the saved project and linked war before assuming it disappeared. `tools/inspect_common_fund_save.py` is read only and must not be turned into a silent save-repair tool.
- Update `docs/MOD-CURRENT-STATE.md`, the affected subsystem tracker and its test checklist after material changes. State exactly what was implemented, what was verified and what remains untested. Do not mark engine tests passed without engine evidence.
- For an engine crash, preserve/read the crash bundle and final logs before attributing it to a script. The 2026-10-29 20:36 crash was an unsymbolized pure-virtual call while opening a character, after live rebuild reloads. Its exact cause is unproven; do not label staging or a speculative gameplay change as a confirmed crash fix.

These instructions do not require another approval for work already authorized by the user. If a new request intentionally changes one of these boundaries, follow that request and document the resulting contract/migration.
